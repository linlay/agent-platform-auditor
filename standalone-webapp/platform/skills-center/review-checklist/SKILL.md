# 审阅清单

适用：用户希望审查一段方案、配置或验收说明是否完整、一致、可验证。

1. 先说明审阅对象和仅依据用户文本的限制。
2. 检查身份和凭证：后端或页面是否读到了 owner JWT、私钥或完整 `.state`；是否把票据放在 URL。
3. 检查权限：是否整体授权 runtime 根目录；是否允许任意子进程、代码写入或越权读写。
4. 检查模块边界、输入校验、重启/失败/回滚以及部署环境的差异。
5. 检查“通过、已交付、全平台”等结论是否有对应环境和实际结果支持。
6. 无证据的问题使用“需要验证”，不要编造已发生的故障。

输出格式：`## 审阅结论`、`## 发现`、`## 修改建议`、`## 验收清单`。
发现用 P1/P2/P3 表示影响，解释触发条件、影响和具体建议。没有发现时明确说明审阅覆盖范围。
